STEP 0

このガイドの使い方

最初にここだけ読んでください。

このプロジェクトには 17 個ほどのドキュメント（.md ファイル）が散らばっています。 全部を最初から読む必要はありません。このガイドは、それらを 読むべき順番に並べ替え、 各ドキュメントが「何のためのものか」「どこに本物のファイルがあるか」を1ページで把握できるようにしたものです。

用語：ドキュメント / .md ファイル 「ドキュメント」は説明書のこと。.md（マークダウン）は、見出しや箇条書きを 簡単な記号で書ける軽量なテキスト形式です。プログラムではなく「人間が読む説明文」が書かれています。

Git・GitHub まわり（コードの保管と共同作業）

リポジトリ repository / repo
プロジェクトのファイル一式と、その変更履歴を丸ごと保管する「箱」。GitHub 上にあります。
クローン clone
GitHub 上のリポジトリを、自分のパソコンにコピーしてくること。
ブランチ branch
作業用の「枝分かれした作業スペース」。本流は main。新機能は別ブランチで作り、完成したら main に合流させます。
コミット commit
変更内容に「ここまでの区切り」とメモ（コミットメッセージ）を付けて記録すること。セーブポイントのようなもの。

自分のパソコンのコミットを、GitHub 側へアップロードすること。

あるブランチの変更を、別のブランチ（多くは main）に合流・統合すること。
プルリクエスト Pull Request / PR

このサイトを動かす技術

Next.js（ネクストジェイエス）
Web サイトを作るための土台ソフト（フレームワーク）。React という仕組みの上に作られています。
App Router（アップルーター）
Next.js の「どのURLでどのページを表示するか」を決める仕組み。src/app/ フォルダの構造が、そのままサイトのURL構造になります。
TypeScript（タイプスクリプト）
JavaScript（Webの基本言語）に「型」というミスを防ぐ仕組みを足した言語。ファイル拡張子は .ts / .tsx。
コンポーネント component
ボタン・ヘッダー・カードなど、画面の「部品」。部品を組み合わせてページを作ります。
SCSS / CSS Modules
見た目（色・大きさ・配置）を指定する言語が CSS。SCSS はその高機能版。「CSS Modules」は、各部品ごとに見た目を閉じ込めて他とぶつからないようにする仕組み。ファイルは .module.scss。
レスポンシブ responsive
PC・タブレット・スマホ、どの画面幅でも崩れず美しく見えるように作ること。
React Three Fiber / Three.js / GLB
Web 上で 3D を表示する技術。.glb は 3D モデルのファイル形式。このサイトには 3D キャラクター演出があります。
GSAP（ジーサップ）
アニメーション（動きの演出）を付けるためのライブラリ。スクロールに連動した動きなどに使います。
WordPress REST API
ニュース記事を WordPress（ブログ管理ツール）側で書き、その内容をこのサイトが受け取って表示する連携の仕組み。このサイトでは「後日連携」予定で、まだ本接続していません。

開発作業まわり

npm（エヌピーエム）
このプロジェクトが使う外部の部品（ライブラリ）をまとめて管理・インストールする道具。npm install で一式そろえます。
開発サーバー dev server
npm run dev で起動する、作りかけのサイトを手元で確認するための仮サーバー。http://localhost:3000 で見られます。
ビルド build
npm run build で実行。コードを「本番公開用」に変換する作業。型のミスなどがあると失敗します。
Lint（リント）/ ESLint
npm run lint で実行。コードの「書き方の品質」を自動チェックする道具。バグになりやすい書き方を警告してくれます。
環境変数 / .env.local
API キーなど「コードに直接書きたくない秘密の設定値」を入れておくファイルが .env.local。GitHub にはアップロードしません（秘密だから）。
Figma（フィグマ）
デザインを作る・閲覧するツール。このサイトのデザイン（完成見本）は Figma にあります。
MCP
Claude Code が Figma などの外部ツールと直接やり取りするための接続規格。デザインの実寸法を自動取得するのに使います。

STEP 3

開発の進め方

元ファイル： docs/DEVELOPER_ONBOARDING.md — 環境構築から最初の PR までの一気通貫ガイド。引き継ぎで一番重要。

3-1. 環境構築（最初の30分）

ターミナルで実行するコマンドgit clone https://github.com/arigatosun/arigatosun_hp.git
cd arigatosun_hp
npm install        # 部品を一式インストール
npm run dev        # 開発サーバー起動

http://localhost:3000 が開けば成功です。

環境変数（.env.local）

プロジェクト直下に .env.local というファイルを作り、秘密の設定値を入れます。

.env.local の中身RESEND_API_KEY=                  # 問い合わせメール送信用。未設定だとビルド失敗
NEXT_PUBLIC_WORDPRESS_API_URL=   # ニュース連携用。未設定でもビルドは通る
重要：.env.local は絶対に GitHub にアップしない 秘密の値（API キー）が入っているためです。.gitignore という仕組みで自動的に除外されていますが、 念のため git add -A（全部追加）を避け、git add <ファイル名> と1つずつ指定する習慣が推奨されています。

3-2. 開発の絶対ルール（破ると PR が差し戻される）

① スケーラブルな値は固定 px 禁止 → fluid() を使う

文字サイズ・余白・幅などは、固定の px で書かず、画面幅で伸縮する @include fluid() で書きます。

// ❌ NG（固定サイズ）
.title { font-size: 48px; margin-top: 80px; }

// ✅ OK（画面幅で 24px〜48px に伸縮）
.title {
  @include fluid(font-size, 24, 48);
  @include fluid(margin-top, 40, 80);
}
解説：fluid() とは このプロジェクト独自の「おまじない」。@include fluid(font-size, 24, 48) は 「文字サイズを、スマホでは 24px・PC では 48px、その間はなめらかに変化させる」という意味です（詳細は STEP 7）。

② 色は CSS 変数経由（#xxxxxx の直書き禁止）

色コードを直接書かず、あらかじめ名前を付けた「変数」で指定します。

// ❌ NG  color: #DA2719;
// ✅ OK  color: var(--color-primary);
解説：CSS 変数 / デザイントークン var(--color-primary) は「ブランドの赤」に付けた名札。色を一箇所で管理でき、表記ゆれも防げます。 使える色の一覧は .claude/rules/design-tokens.md にあります。

③ コンポーネントは「3点セット」で作る

src/components/ui/MyComponent/
├── MyComponent.tsx          # 部品の中身（HTML構造・動き）
├── MyComponent.module.scss  # 見た目
└── index.ts                 # 読み込み用の入口

④ 横並び2カラムは、スマホで縦積みにする対応を必ず入れる

.row {
  display: flex;            # PCでは横並び
  gap: 40px;
  @include sp {             # スマホ＆タブレット（1023px以下）では
    flex-direction: column; #   縦並びに切り替え
    gap: 24px;
  }
}

STEP 6

実装ルール（.claude/rules/ — 8ファイル）

元ファイル： .claude/rules/ フォルダ内の8つの .md。コードを書く直前に、該当するものを読む設計です。

responsive.md 最重要

このプロジェクトの根幹。「固定 px 禁止、必ず fluid()」というルールと、 スマホ時の最小値（min）の算出テーブルが書かれています。詳細は STEP 7。

design-tokens.md

使ってよい色・フォント・余白などの「正解リスト」。たとえば ブランド赤は --color-primary（#DA2719）、文字色は --color-black（#140700）。 新しい色が必要なら、先に _variables.scss に定義してから使います。

coding-standards.md

TSX / SCSS の書き方・命名規約。コンポーネント名は PascalCase（例 MemberSection）、 CSS クラス名は camelCase（例 memberCard）、import の順序、など。

component-creation.md

新しい部品を追加するときの手順。「3点セット」で作る、置き場所の判断（layout / ui / three）、 'use client' を付ける条件など。

解説：'use client' とは Next.js では部品が2種類あります。'use client' を付けると「ブラウザ側で動く部品」になり、 クリックや状態変化・アニメーションが扱えます。付けない部品は表示専用で軽量。迷ったら付けない側に倒す、が原則です。

design-to-implementation.md

Figma のデザイン値を、どう SCSS コードに変換するかの実装手順。 「Figma の値 = 最大値、最小値はテーブルから算出」という流れ。

figma-mcp-workflow.md

Figma のデザインから、寸法・色などの実測値を MCP 経由で自動取得する手順。 Figma デスクトップアプリで「Dev Mode MCP Server」をオンにする必要があります。

asset-management.md

画像・3D モデルの置き場所と命名ルール。ファイル名は 小文字＋ハイフン区切り（例 hero-bg.png）。 画像は next/image を使い、alt（代替テキスト）を必ず付ける、など。

pre-commit-checklist.md

コミット直前のチェックリスト。npm run lint / npm run build がエラー0、 4幅でのレスポンシブ目視、色・固定 px の点検、不要な console.log 削除など。

docs/ と .claude/rules/ の役割の違い .claude/rules/ は Claude Code が状況別に参照する短いルール。 docs/ は 人間が腰を据えて読む詳しい資料。同じ内容を両方に書かない方針です。
STEP 7

レスポンシブ設計の詳細（このプロジェクトの心臓部）

元ファイル： docs/RESPONSIVE_GUIDE.md / docs/DEVELOPMENT.md / .claude/rules/responsive.md

設計思想：Fluid Design（フルイドデザイン）

従来のレスポンシブは「スマホ用」「PC用」とパッと切り替える方式でした。 このプロジェクトは clamp() という CSS 機能を使い、 画面幅に応じて文字や余白をなめらかに連続変化させます。

解説：clamp() とは CSS の機能で「最小値・推奨値・最大値」を渡すと、画面幅に応じて値がその範囲でなめらかに変わります。 このプロジェクトでは fluid() がこの clamp() を自動生成してくれます。

fluid() の使い方

入力（SCSS に書くもの）@include fluid(font-size, 14, 24);

↓ 自動生成される本物の CSSfont-size: clamp(0.875rem, 0.511rem + 1.136vw, 1.5rem);

// 結果： 画面320px時は14px、1200px時は24px、その間はなめらかに変化
引数意味
第1引数CSS プロパティ名（font-size, padding, gap など）
第2引数最小値（スマホ＝320px時のデザイン値）
第3引数最大値（PC＝1200px時のデザイン値＝Figma の値）

最小値（min）の決め方の目安

Figma には PC のデザインしか無い場合が多いので、スマホ用の最小値は次の比率で見積もります。

用途PC値(max)スマホ値(min)の目安
大見出し38〜44pxPC値 × 約0.50〜0.55
本文（日本語）24〜26px14px（最小可読サイズ）
余白（margin/padding）—PC値 × 約0.30〜0.50

ブレイクポイント（レイアウトの切り替え）

fluid() は「サイズの伸縮」担当。「横並び→縦並び」のような構造の変更には ブレイクポイントを使います。

@include sp  { ... }   // スマホ：〜767px
@include tab { ... }   // タブレット：768〜1023px
@include pc  { ... }   // PC：1024px〜
確認用の4つの幅 実装後は必ず 320px / 375px / 768px / 1200px の4幅で見た目を確認します。 ブラウザの開発者ツール（F12 →「デバイスツールバー」）で幅を切り替えられます。

STEP 9

Claude Code 活用のコツ

元ファイル： docs/CLAUDE_CODE_HACKS.md — このプロジェクトを動かす上での開発スタイル集。

このプロジェクトは、AI コーディングツール「Claude Code」を使う前提で設計されています。 前任者がまとめた、効率よく使うコツの抜粋です。

  • コードを書く前に方針を出させる：いきなり実装させず、まず構造提案を文章で出させると手戻りが激減する。
  • ビルド・lint は Claude にやらせる：npm run build を実行させ、出たエラーをそのまま渡してデバッグさせる。
  • 同じミスをしたら rules/ に追記：Claude が繰り返すミスは、ルール不足。.claude/rules/ にアンチパターンを足せば次から回避される。
  • コミットメッセージを下書きさせる：git diff を渡して日本語で要約させる。ただし最終確認は自分で。
  • 具体的に聞く：ふわっと聞かず、ファイルパス・行番号を添えて、該当ファイルを読ませながら質問する。
困ったときの優先順位（DEVELOPER_ONBOARDING より） ① CLAUDE.md の目次から該当 rules を読む → ② Claude Code に「該当ファイルを読んだ上で教えて」と聞く → ③ docs/ の詳細資料 → ④ それでも詰まったら管理者に連絡（k2@arigatosun.com）。
