NEWS ADMIN MANUAL

ニュース管理画面マニュアル

株式会社アリガトサン コーポレートサイト

対象: サイト管理者・編集担当 管理画面 URL: /admin 公開ニュース URL: /news
SECTION 1

このシステムでできること

サイトの「NEWS」コーナーに表示される記事を、Web ブラウザだけで作成・編集・公開できる管理画面です。

主な機能

  • 記事の作成・編集・削除（タイトル / 本文 / カテゴリー / サムネ画像）
  • 下書き保存と公開の切り替え（公開日時を未来に指定すれば予約公開も可能）
  • リッチエディタでの本文編集（見出し・太字・リスト・画像・テーブル・リンクなど）
  • 画像のアップロード（サムネと本文中の挿入画像）
  • カテゴリーの追加・編集・削除（初期値: INFORMATION / EVENTS / PRESS）

このマニュアルの対象範囲

サイト管理者として「記事の投稿〜公開」「画像のアップロード」「カテゴリーの管理」を行う方を対象に、操作手順と仕様を解説します。

📘 関連ドキュメント 技術的な開発ガイドは docs/DEVELOPER_ONBOARDING.md / CLAUDE.md を参照してください。
SECTION 2

アクセス方法

管理画面はブラウザでアクセスします。

ローカル開発環境

  1. ターミナルでプロジェクトディレクトリに移動し npm run dev で開発サーバーを起動
  2. ブラウザで http://localhost:3000/admin を開く
  3. 未ログインなら自動でログイン画面にリダイレクトされる

本番環境

本番ドメイン（例: https://arigatosun.com）に /admin を付けてアクセスします。

⚠ 注意 管理画面は noindex, nofollow が指定されており検索エンジンにはインデックスされません。直接 URL を知っている人だけがアクセスできます。
SECTION 3

はじめてのログイン

最初の管理者ユーザーは Supabase ダッシュボードで作成する必要があります（自己登録は不可）。

管理者ユーザーが未作成の場合

  1. Supabase ダッシュボードを開く（プロジェクト URL は開発者から共有されます）
  2. 左メニュー Authentication → Users へ移動
  3. Add user → Create new user をクリック
  4. メールアドレスとパスワード（8文字以上）を入力
  5. Auto Confirm User にチェックを入れて作成

ログインする

  1. /admin または /admin/login にアクセス
  2. メールアドレスとパスワードを入力し、ログイン をクリック
  3. 成功すればダッシュボード（/admin）にリダイレクト
⛔ 失敗するパターン
  • 「Invalid login credentials」: メアド or パスワードが間違っています
  • 「Email not confirmed」: 作成時に Auto Confirm を入れ忘れた → Supabase 側で再度確認
SECTION 4

ダッシュボードの見方

ログイン後の /admin がダッシュボードです。

画面構成

  • ヘッダー左: ARIGATOSUN Admin ロゴ（ダッシュボードへのリンク）
  • ヘッダー中央: ナビゲーション（ダッシュボード / ニュース / カテゴリー）
  • ヘッダー右: ログイン中のメールアドレス + サインアウト ボタン
  • 本文: 件数カード4枚と「新規作成」「記事一覧」へのショートカット

カードの意味

カード表示される件数
下書きstatus = 'draft' の記事
公開中status = 'published' かつ公開日時が現在以前
予約公開status = 'published' かつ公開日時が未来
カテゴリーカテゴリー全体の件数

カードをクリックすると、それぞれフィルター済みの一覧ページに遷移します。

SECTION 5

記事を投稿する基本フロー

新規作成から公開までの最短手順です。

  1. ヘッダーの ニュース をクリック → + 新規作成 をクリック
  2. 必須項目を入力:
    • タイトル（200文字以内）
    • スラッグ（URL 用、半角英小文字・数字・ハイフン）
    • カテゴリー（ドロップダウンから選択）
  3. 任意項目を入力:
    • サムネイル画像（一覧と詳細ページに使用）
    • 本文（リッチエディタ）
    • 公開日時（空欄なら「公開する」押下時の現在時刻が使われる）
  4. フッターのボタンで保存:
    • 下書きとして保存 — まだ公開しない
    • 公開する — 公開状態にする
  5. 成功すると編集画面（/admin/news/[id]/edit）に遷移し「記事を作成しました」バナー表示
💡 スラッグについて

公開 URL は /news/[公開年]/[スラッグ] になります。例えば spring-event を 2026 年に公開すれば /news/2026/spring-event です。

スラッグは 同じ年内で重複不可。違う年なら同じ文字列を使い回せます。

編集する

  1. ニュース一覧の記事タイトル or 編集 をクリック
  2. 内容を書き換え
  3. 下部のボタンで保存（ボタン文言は現在のステータスに応じて変化、後述）

削除する

削除はニュース一覧の行内 削除 ボタン、または編集画面下部の「危険な操作」セクションから行います。確認ダイアログが出ます。

⛔ 削除は取り消し不可 削除すると DB から完全に消えます。Storage 上の画像ファイルは 連動して削除されない ので、必要なら Supabase ダッシュボードから手動削除してください。
SECTION 6

公開状態（下書き / 公開中 / 予約公開）

記事は2つの状態（draft / published）と公開日時の組み合わせで管理されます。

3つの表示状態

表示条件公開ページでの可視性
下書き status = 'draft' 非表示
公開中 status = 'published' かつ公開日時 ≤ 現在 表示される
予約公開 status = 'published' かつ公開日時 > 現在（未来） 公開日時まで非表示

ボタンの挙動（編集画面）

現在の状態に応じてボタン文言が切り替わります。

下書きを編集中

  • 下書きとして保存: 下書きのまま更新
  • 公開する: status を published に変更

公開中の記事を編集中

  • 下書きに戻す: 非公開化（確認ダイアログあり）
  • 公開情報を更新: 公開状態のまま内容を保存

予約公開の使い方

  1. 編集画面の 公開日時 に未来の日時を入力
  2. 公開する または 公開情報を更新 をクリック
  3. ステータスバッジが 予約公開 に変わる
  4. 指定日時が到来すると、公開ページに自動で出現（cron 不要）
💡 仕組み 公開ページは「status='published' かつ published_at ≤ 現在」という条件で記事を取得します。未来日時の記事はクエリ結果に含まれないので、時刻が来た瞬間に表示されるようになります。
SECTION 7

リッチエディタの使い方

本文は TipTap ベースのリッチエディタで編集します。書いた内容は TipTap JSON 形式で DB に保存され、公開時に HTML へ変換されます。

リンクの挿入

  1. リンクにしたいテキストを選択
  2. ツールバーの リンク ボタンをクリック
  3. URL 入力プロンプトが出るので、https://... を入力
  4. OK で確定。リンクを解除したい時は同じボタンを押して空欄で OK
⚠ 安全なリンクのみ許可 javascript: など危険なプロトコルは TipTap 側で自動的に弾かれます。許可されるのは http / https / mailto / tel など標準的なものです。

画像の挿入

ツールバーの 画像 ボタンをクリック → ファイル選択ダイアログから画像を選ぶと、自動でアップロードされカーソル位置に挿入されます。サムネイルとは別の場所（本文中）に表示されます。

テーブルの編集

テーブルを挿入すると 3×3 のテーブルが入ります。セル内をクリックして入力可能です。行・列の追加/削除はキーボード操作またはマウスの右クリックメニュー（ブラウザ依存）で行います。

下書きの仕組み

エディタの内容は入力するたびに 非表示のフィールドに JSON として記録 されています。保存ボタンを押すと、その JSON が DB の news.content（jsonb）に保存されます。

⛔ 自動保存はありません ページを離れる前に必ず「下書きとして保存」or「公開する」を押してください。書きかけのまま閉じると内容は失われます。
SECTION 8

画像のアップロード

サムネ画像と本文内挿入画像の2種類。どちらも仕様は共通です。

サムネイル画像

  1. 編集画面の「サムネイル画像」セクションで 画像をアップロード をクリック
  2. ファイルを選択 → アップロード後にプレビューが表示
  3. 差し替える時は 別の画像をアップロード、削除する時は 削除 ボタン

本文内の画像

リッチエディタの 画像 ツールバーボタンから挿入。

アップロード制限

項目制限
ファイルサイズ5MB 以下
形式JPEG / PNG / WebP / GIF
保存先Supabase Storage news-images バケット
保存パスnews/[公開年]/[UUID].[拡張子]（衝突しない）
公開 URLhttps://[supabase-host]/storage/v1/object/public/news-images/...
💡 多重防御 制限はアプリ側（管理画面）と DB バケット側（Supabase Storage の設定）の両方で同じ値が設定されています。仮にアプリ側のチェックを迂回しても、DB レベルで弾かれます。
⛔ 不要画像のクリーンアップ 記事を削除しても、その記事で使われていた画像ファイルは Storage に残り続けます。気になる場合は Supabase ダッシュボードの Storage → news-images から手動で削除してください。
SECTION 9

カテゴリー管理

ニュース記事に紐付けるカテゴリーを管理します。初期値は INFORMATION / EVENTS / PRESS の3つ。

画面構成

ヘッダーの カテゴリー リンクから /admin/categories へ。各カテゴリーは独立したフォームの行として表示されます。

新規追加

  1. ページ下部の「新規追加」フォームに入力:
    • スラッグ: 半角英小文字・数字・ハイフン（最大50文字）
    • ラベル: 一覧などに表示される名前（最大100文字）
    • 表示順: 数値（自動で次の番号がセットされる）
  2. + 追加 をクリック

編集

既存カテゴリーの行で値を書き換えて 保存 ボタン。

削除

  1. 該当行の 削除 ボタン
  2. 確認ダイアログで OK
⛔ 記事に使われているカテゴリーは削除不可 そのカテゴリーを参照している記事が1件でもあれば「このカテゴリーは記事で使用中のため削除できません」とエラーが出ます。先に記事側のカテゴリーを変更してから削除してください。
📘 表示順について 数値が小さい順に並びます。公開ページのカテゴリータブもこの順番です。間に挿入したい時は中間の数値（例: 1.5 → 整数のみなので不可なら 1, 2, 3, 4 を 1, 3, 5, 7 等にリナンバ）を使ってください。
SECTION 10

公開ページの動作

投稿した記事は /news 配下に表示されます。

URL 構造

URL内容
/news記事一覧（最新順、ページネーション、カテゴリーフィルター）
/news?category=informationカテゴリー絞り込み（slug で指定）
/news?page=22ページ目（1ページ6件）
/news/[公開年]/[スラッグ]記事の詳細ページ

表示される条件

  • status が published である
  • かつ 公開日時 ≤ 現在時刻

下書きや予約公開（未来日時）は 公開ページからは絶対に見えません。直接 URL を叩いても 404 になります。

キャッシュ

公開側は ISR（Incremental Static Regeneration）で 60 秒キャッシュ。記事を保存しても最大 60 秒は古い表示が出ることがあります。

TOP ページのニュースセクション

サイト TOP には最新4件の記事が出ます。こちらはブラウザ側で Supabase から直接取得し、カテゴリータブで動的にフィルタできます。

SECTION 11

管理者アカウントの追加・削除

管理画面にログインできるユーザーの管理は Supabase ダッシュボードで行います（管理画面内にはユーザー管理 UI を用意していません）。

追加する

  1. Supabase ダッシュボード → Authentication → Users
  2. Add user → Create new user
  3. Email・Password を入力し Auto Confirm User にチェック
  4. Create user

削除する

  1. 同じ Users 画面でユーザー行の右端 ⋯ メニュー
  2. Delete user

パスワードを変更する

本人が変更する仕組みは現在の管理画面には実装していません。Supabase ダッシュボードのユーザー詳細画面から管理者がリセット用 URL を発行するか、新パスワードで直接更新してください。

⚠ 設計方針 本サイトは「2〜3名の信頼できる管理者のみ」が想定運用。自己登録機能や複雑な権限管理は意図的に省いています。管理者を増やす場合は必ず Supabase ダッシュボード経由で手動追加してください。
SECTION 12

セキュリティと制限事項

運用前に把握しておくべき仕様。

認証の三層防御

  1. Middleware（/admin/*）: 未ログインなら /admin/login に強制リダイレクト
  2. Layout 側: Server Component で再度 auth.getUser() 確認
  3. Server Action 側: 各保存・削除アクションの先頭でも auth.getUser() 確認

このうちどれか1つを突破されても、他で必ず弾かれます。

RLS（Row Level Security）

テーブル匿名ユーザー（anon）ログイン中ユーザー（authenticated）
news公開済み記事のみ SELECT 可能（status=published かつ published_at <= 現在）全件 SELECT / INSERT / UPDATE / DELETE
categories全件 SELECT 可能全件 SELECT / INSERT / UPDATE / DELETE
storage.objects（news-images）公開 URL 経由でファイル取得のみnews/ 配下のみ INSERT / UPDATE / DELETE

画像アップロードの安全策

  • MIME タイプは アプリ側 + DB バケット側 の両方で許可リストに制限
  • ファイルサイズも両層で 5MB 制限
  • ファイル名はサーバー生成の UUID（パストラバーサル不可）
  • 保存先は news/ プレフィックスに限定

本文 HTML の安全性

  • 本文は TipTap JSON で保存 → 公開時に HTML 変換
  • TipTap は許可されたノード・属性のみ出力するため、<script> 等は混入不可
  • リンクのプロトコルも標準的なもののみ（javascript: は不可）
💡 信頼モデル 本システムは「ログインできた人 ＝ 信頼できる管理者」前提です。コンテンツの厳密なサニタイズは行っていないので、悪意のある管理者を想定する場合は別途対策が必要です（管理者を増やす時は信頼できる相手のみに限定）。
SECTION 13

トラブルシューティング

よくある詰まりポイントと対応。

ログインできない

  • 「Invalid login credentials」: メアドかパスワードが違います。Supabase ダッシュボードで該当ユーザーを確認
  • 「Email not confirmed」: ユーザー作成時に Auto Confirm User にチェックを入れ忘れた。Supabase ダッシュボードでユーザー詳細を開き「Confirm email」を実行
  • ページが真っ白: 開発サーバーが起動していない、または環境変数（.env.local）が未設定の可能性

記事を保存できない

  • 「同じ年に同じスラッグの記事が既に存在します」: そのスラッグは既に使われています。違うスラッグに変更してください
  • 「タイトルを入力してください」「スラッグを入力してください」: 必須項目が空
  • 「半角英小文字・数字・ハイフンのみ使用できます」: スラッグに使えない文字（大文字や日本語など）が含まれている
  • 「サムネイル画像は管理画面のアップローダーから設定してください」: thumbnail_url を直接編集した場合（通常は ImageUploader 経由なので発生しない）

画像アップロードに失敗する

  • 「ファイルサイズは 5MB 以下にしてください」: 制限超過。画像を圧縮してから再アップロード
  • 「対応形式は jpg / png / webp / gif のみです」: HEIC や TIFF などは不可。PNG/JPEG に変換
  • 「認証が必要です」: セッションが切れた。再ログインしてください
  • サムネプレビューが出ない: next.config.ts の images.remotePatterns に Supabase URL が登録されているか確認（通常設定済み）

カテゴリーを削除できない

  • 「このカテゴリーは記事で使用中のため削除できません」: そのカテゴリーを使っている記事を先に別カテゴリーに変更するか削除する

公開したのに /news に出ない

  • 公開日時が未来になっていないか確認（予約公開状態）
  • キャッシュの可能性。最大60秒待ってからページを再読み込み
  • ブラウザのハードリロード（⌘⇧R / Ctrl+F5）も試す

下書きが公開側に見えてしまう

これは本来起こらない実装。もし発生した場合は重大なバグなので開発者に報告してください。ヒント: 同じブラウザで admin にログイン中だと、シークレットウィンドウで確認すると分かりやすいです。

用語集

用語意味
スラッグ (slug) URL の一部に使う識別子。半角英小文字・数字・ハイフンで構成。例: spring-event-2026
下書き (draft) 未公開の状態。管理画面からのみ閲覧可能
公開中 (published) 誰でも閲覧できる状態
予約公開 「公開」状態だが公開日時が未来。時刻が来ると自動で公開される
カテゴリー 記事を分類するためのタグ的なもの。1記事につき1つ
サムネイル 一覧と詳細で表示される代表画像。本文中の挿入画像とは別管理
TipTap 本文編集に使っているリッチエディタライブラリ
Supabase DB・認証・ストレージを提供するサービス。データの実体はここに保存される
RLS（Row Level Security） DB レベルで「誰がどのデータを見れるか」を制御する仕組み。下書きが公開側に漏れないよう保護
Server Action ブラウザからのフォーム送信時にサーバー側で実行される関数。保存・削除などの実処理を担う
ISR（Incremental Static Regeneration） ページを一定時間キャッシュし、期限切れに合わせて再生成する仕組み。本サイトの公開ページは60秒
